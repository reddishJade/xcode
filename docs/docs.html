Xcode 设计理念与核心实现Design Philosophy & Core Implementation

Xcode 并不是一组大模型 API 与本地脚本的简单组合（薄包装），而是一个面向生产环境的 Python Coding Agent 运行时骨架（Runtime Harness）。核心围绕 可测试性（Testability）、可观测性（Observability） 与 纵深防御（Defense-in-depth） 进行架构设计。 Xcode is not a thin API wrapper, but a production-grade Python Coding Agent Runtime Harness architected around testability, observability, and defense-in-depth.

八大核心设计机制Eight Core Architectural Mechanisms

1. 可回放事实账本 Authoritative

所有输入、模型 Envelope（provider_request）、工具调用与 Checkpoint 均以 Append-only JSONL 落盘。状态皆为日志投影。All prompts, provider envelopes, tool results, and checkpoints are appended to JSONL. All state is a log projection.

2. 模式与分权管理 Plan / Build

Plan 严格只读（仅写规划 Markdown）；Build 模式写入业务代码并通过独立 Reviewer 模型自动审查 Shell 命令。Plan is strictly read-only; Build allows project writes with automated Reviewer semantic policy checks.

3. Linux Bubblewrap 沙箱 Hardened

命名空间隔离；宿主只读；项目可写；.git/.xcode 重新只读保护；密钥目录与 .env* 全面遮蔽；网络隔离。Linux namespaces: host read-only, project write, read-only .git/.xcode, masked secrets (.env*), network isolation.

4. 副作用感知并发分区 Concurrent

并发安全的只读工具并行派发；写操作串行屏障；edit_file 强制基于读取时的 SHA256 指纹校验防脏写。Concurrent read worker pools, serial write barriers, and Read-before-edit SHA256 fingerprinting.

5. 分层上下文压缩 70% Threshold

达到 70% 水位线触发；分层裁剪过期文件全文；保留滚动 Checkpoint；通过快照与增量尾部实现毫秒级恢复。70% trigger: prunes stale reads, maintains rolling checkpoints, and enables instant resume via Checkpoint + Tail.

6. Durable 子代理谱系 Session-backed

子代理是一等公民持久化 Session；谱系追溯；退出时采用 Child-first 逆序生命周期回收，杜绝孤儿进程。Subagents are durable sessions with lineage tracking and child-first reverse lifecycle cleanups.

7. 中途可打断与取消安全 Interruptible

中断时秒级 Cancel 底层 HTTP 流；安全终止后台工具与沙箱进程；记录 run_aborted 事件保持一致性。Mid-run stream cancellation, graceful sandbox termination, and run_aborted event recording.

8. 类型化渲染意图 Typed Intents

工具返回结构化 DiffIntent、TerminalIntent 等语义对象，彻底解耦计算、I/O 与终端展示层。Tools return structured DiffIntent and TerminalIntent, decoupling computation, I/O, and TUI presentation.

五大系统级核心不变量Five Core System Invariants

01

不可丢弃历史 (No State Lost)No State Lost

任何会话状态均可从 JSONL 事实账本完全重建，禁止任何原地修改或隐式状态丢失。All session states can be completely reconstructed from JSONL logs; in-place mutations are forbidden.

02

不可越界执行 (No Boundary Bypass)No Boundary Bypass

非只读操作与跨工作区写入必须经过权限引擎与沙箱边界校验，禁止任何绕过审批的副作用。Write operations outside the workspace must pass PermissionEngine and sandbox checks.

03

可见即已记录 (Visible Equals Recorded)Visible Equals Recorded

大模型接收到的每一条 Wire Message 必须与账本中落盘的 provider_request 记录完全一致。Every wire message delivered to the LLM must match the logged provider_request envelope.

04

编辑幂等防脏写 (Read-before-edit Verification)Read-before-edit Verification

所有文件修改必须基于读取时的 SHA256 指纹校验，杜绝多工具调用或外部修改导致的脏覆盖。All file edits must validate the SHA256 checksum at read-time to prevent race dirty writes.

05

经验量化验证 (Empirical Gating)Empirical Gating

所有关键架构决策（如分层压缩算法、并发调度优化）必须拥有对应的真实消融 Benchmark 支撑。All core architectural decisions must be grounded in ablation benchmarks.

五层系统架构与单向数据流Five-Layer Architecture & Unidirectional Flow

Xcode 采用严格的五层分层架构，数据流向始终由高层向底层单向流动，每一层均可独立编写单元测试与契约测试。 Xcode enforces a strict 5-layer design where dependencies flow unidirectionally from high-level interaction to low-level adapters.

数据流：高层 → 低层，单向依赖，逐层可测

多 Profile 角色分工架构Multi-Profile Role Allocation

在 xcode.config.json 中可以为主会话 (main)、自动化审查器 (reviewer) 和子代理 (subagent) 分配不同的模型策略：Assign specialized models and reasoning efforts to main, reviewer, and subagent roles:

xcode.config.json
{
  "provider": {
    "default_transport": "deepseek_chat",
    "model_profiles": {
      "main": {
        "transport": "deepseek_chat",
        "chat_model": "deepseek-v4-flash",
        "thinking": true,
        "reasoning_effort": "high"
      },
      "reviewer": {
        "transport": "deepseek_chat",
        "chat_model": "deepseek-v4-flash",
        "thinking": false
      },
      "subagent": "deepseek-v4-flash"
    }
  }
}

会话账本、分层压缩与快照撤销Sessions, Layered Compaction & Snapshot Undo

全量事件流持久化；70% 上下文水位线分层裁剪；支持多分支分叉与文件级快照秒级撤销。 Authoritative session event log, 70% threshold layered compaction, and instant file snapshot undo.

70% 水位线分层压缩机制 (Layered Compactor)70% Threshold Layered Compactor

当上下文累计达到模型预留窗口的 70% 时，系统自动触发非侵入式分层压缩：When prompt size exceeds 70% of context capacity, Xcode triggers layered pruning:

  • 第一层：裁剪陈旧只读输出 —— 移除早前轮次中大型 read_file 与 grep_search 的冗长全文；
  • 第二层：截断历史工具执行结果 —— 压缩陈旧的命令标准输出，保留返回状态码与核心错误提示；
  • 第三层：生成状态 Checkpoint —— 归纳已完成的架构决策与待办任务列表并落盘快照；
  • 极速恢复：后续会话恢复直接加载 Checkpoint 快照 + 原文尾部事件，Token 消耗降低 60% 以上。

权限引擎与 Linux 沙箱Security, Permissions & Linux Sandbox

PermissionEngine 规则鉴权、Reviewer 语义风控与 Linux Bubblewrap 命名空间进程硬化隔离。 PermissionEngine, Reviewer model risk assessment, and Linux Bubblewrap namespace isolation.

三层纵深防御架构Three-Tier Defense-in-depth Architecture

01

决策层：PermissionEngine 静态规则判定Tier 1: PermissionEngine Static Gating

通过 findLast 规则覆盖引擎，根据工具名称、Shell 命令前缀及路径通配符决定放行、拒绝或请求确认。Matches rules using findLast semantics based on tool name, shell command, and path globs.

02

审查层：Reviewer Profile 动态语义风控Tier 2: Reviewer Profile Semantic Analysis

在 Build 模式下，对于 Shell 命令和边界写操作，由轻量 Reviewer 模型分析其破坏性与依赖影响，低风险操作自动秒级放行。In Build mode, the Reviewer model evaluates commands semantically to auto-approve low-risk actions.

03

隔离层：Linux Bubblewrap OS 命名空间沙箱Tier 3: Linux Bubblewrap Namespace Sandbox

Linux 环境下所有 Shell 执行均放入 bwrap 沙箱中运行，提供不可穿透的操作系统级防御。All shell executions run inside a bwrap container with namespace-level isolation.

Subagents 子代理架构Subagents Architecture

基于独立 Durable Session 的子代理委派，具备独立谱系追溯、Context 预算隔离与 Child-first 逆序回收。 Durable session-backed subagents with lineage tracking, isolated context budgets, and child-first cleanup.

子代理协作机制Subagent Collaboration Mechanisms

1. 独立事实账本 Isolated

子代理拥有独立的 Session ID 与 JSONL 账本，避免子任务长篇输出污染主会话上下文。Subagents run on dedicated session logs, preventing prompt bloating in the main conversation.

2. 谱系追溯与监控 Lineage

账本记录 subagent_run_created 事件，明确父子调用关系与运行时上下文。Tracks subagent_run_created events for parent-child lineage auditing.

3. Child-first 逆序回收 Safe Settle

会话关闭或中断时，严格逆序等待子代理收敛，防止孤儿进程与文件损坏。Ensures graceful reverse teardown to prevent orphaned processes or disk corruption.

外部事件 HooksExternal Event Hooks

在工具执行前后注入自定义命令，通过 JSON Stdin/Stdout 实现动态策略拦截与自动格式化联动。 Attach external scripts before or after tool runs for dynamic policy gating and formatting.

Hook 配置范例Hook Configuration

xcode.config.json
{
  "hooks": {
    "entries": [
      {
        "event": "pre_tool",
        "tool": "bash",
        "command": "./scripts/check_dangerous_commands.sh"
      },
      {
        "event": "post_tool",
        "tool": "edit_file",
        "command": "uv run ruff format src/"
      }
    ]
  }
}

实战场景与工作流指南Real-World Workflows & Scenarios

覆盖日常特性开发、重构调研、分支探索、MCP 扩展与沙箱测试等典型实战场景。 End-to-end practical walkthroughs for feature development, refactoring, and tool integrations.

场景 1：大型陌生项目代码理解

启动 xcode 输入 /plan 梳理系统架构与核心数据流，Agent 并发读取关键模块并在 .xcode/plans/ 下输出完备架构说明。Explore foreign codebases in Plan mode with concurrent reading and zero side effects.

场景 2：Plan 到 Build 两阶段新特性

先用 /plan 明确接口方案与测试用例，审阅无误后输入 /build，由沙箱与 Reviewer 自动化编写代码并运行测试。Two-stage development: design under Plan, then execute autonomously under Build.

场景 3：架构重构与一键快照撤销

尝试对核心基类进行重构，若重构后基准测试未通过，输入 /undo 毫秒级将所有文件回退至修改前状态。Safely refactor complex modules with instant file-level atomic /undo rollback.

场景 4：MCP 数据库分析联动

配置 SQLite MCP 服务后，直接提问 查询用户表结构并生成对应 Pydantic 模型，Agent 自动调用 MCP 工具完成。Seamlessly query databases via MCP stdio servers to generate models and migrations.
